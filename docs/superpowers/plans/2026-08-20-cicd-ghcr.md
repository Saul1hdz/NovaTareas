# Plan de implementación: CI/CD con GHCR y seguridad

> **Para agentes ejecutores:** SUB-SKILL OBLIGATORIA: usar
> `superpowers:subagent-driven-development` (recomendado) o
> `superpowers:executing-plans` para implementar tarea a tarea. Los pasos usan
> casillas (`- [ ]`) para seguimiento.

**Objetivo:** que producción corra exactamente la imagen que CI validó, y que el
pipeline compruebe la seguridad de la cadena de suministro antes de publicarla.

**Arquitectura:** un único workflow con tres trabajos — `calidad` (pruebas
actuales), `imagen` (construye, migra con la propia imagen, arranca, escanea con
Trivy y publica en GHCR solo desde `main`) y `seguridad` (npm audit, Gitleaks,
CodeQL) en paralelo. El despliegue al VPS lo sigue ejecutando Argus, ahora con
`docker pull` de la imagen publicada en vez de reconstruir.

**Stack:** GitHub Actions, Docker, GHCR, Trivy, Gitleaks, CodeQL, Dependabot.

**Spec:** `docs/superpowers/specs/2026-08-20-cicd-ghcr-design.md`

## Cómo se prueba un workflow

No hay tests unitarios para GitHub Actions. El ciclo de cada tarea es:

1. Editar el YAML.
2. Validar la sintaxis en local con `actionlint` vía Docker (no hace falta
   instalarlo):
   ```bash
   docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest -color
   ```
3. Commit y push.
4. Observar la ejecución real: `gh run watch --exit-status`.
5. Confirmar el resultado leyendo la salida, no suponiéndolo.

`gh run watch --exit-status` devuelve código distinto de cero si el run falla,
así que sirve como puerta y no solo como espectáculo.

### Tarea 2: Trabajo de seguridad

Aditivo: no toca nada de lo que ya funciona. Si falla, falla solo.

**Ficheros:**
- Modificar: `.github/workflows/ci.yml`
- Crear: `.github/dependabot.yml`

**Interfaces:**
- Consume: el `ci.yml` con cabecera de gobierno de la tarea 1.
- Produce: un job `seguridad` independiente, sin `needs`, que corre en paralelo
  con `calidad`.

- [ ] **Paso 1: añadir el trabajo de seguridad al final de `ci.yml`**

```yaml
  seguridad:
    name: Cadena de suministro
    runs-on: ubuntu-latest
    timeout-minutes: 15

    # Sin `needs`: no depende de las pruebas, así que corre en paralelo y no
    # alarga el reloj del pipeline.
    permissions:
      contents: read
      security-events: write   # publicar hallazgos de CodeQL
      actions: read

    steps:
      - name: Descargar el código
        uses: actions/checkout@v7.0.1
        with:
          # Gitleaks necesita el historial completo: un secreto borrado en el
          # último commit sigue estando en los anteriores y sigue expuesto.
          fetch-depth: 0

      - name: Configurar Node.js 22
        uses: actions/setup-node@v7.0.0
        with:
          node-version: '22.23.1'
          cache: npm

      - name: Instalar dependencias
        run: npm ci

      # Umbral `high` y no `moderate` a propósito: una puerta que salta cada
      # semana por algo que no afecta acaba desactivada, y una puerta
      # desactivada no protege nada.
      - name: Auditar dependencias
        run: npm audit --audit-level=high

      # Saul1hdz es cuenta personal, no organización: no requiere licencia.
      - name: Buscar secretos en el historial
        uses: gitleaks/gitleaks-action@v3.0.0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Preparar CodeQL
        uses: github/codeql-action/init@v4
        with:
          languages: javascript-typescript

      - name: Analizar el código con CodeQL
        uses: github/codeql-action/analyze@v4
```

- [ ] **Paso 2: crear `.github/dependabot.yml`**

```yaml
  imagen:
    name: Imagen de produccion
    needs: calidad
    runs-on: ubuntu-latest
    timeout-minutes: 25

    permissions:
      contents: read
      packages: write   # unico trabajo que puede publicar en GHCR

    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: novatareas
          POSTGRES_PASSWORD: ci-password-ficticia
          POSTGRES_DB: novatareas_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U novatareas -d novatareas_test"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10

    env:
      IMAGEN: ghcr.io/saul1hdz/novatareas
      DATABASE_URL: postgresql://novatareas:ci-password-ficticia@127.0.0.1:5432/novatareas_test
      SECRET_KEY: clave-solo-para-pruebas-de-ci
      CRON_SECRET: cron-solo-para-pruebas-de-ci
      TELEGRAM_WEBHOOK_SECRET: telegram-solo-para-pruebas-de-ci
      TOKEN_ENCRYPTION_KEY: MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY

    steps:
      - name: Descargar el código
        uses: actions/checkout@v7.0.1
        with:
          # `fetch-depth: 2` y no el 1 por defecto: el resumen para Argus de la
          # tarea 4 compara `HEAD~1` con `HEAD` para detectar migraciones
          # nuevas, y con un solo commit descargado ese `HEAD~1` no existe.
          fetch-depth: 2

      - name: Construir la imagen de producción
        run: docker build --target runtime -t novatareas:ci .

      # Migrar con la propia imagen reproduce el servicio `migrate` de
      # compose.prod.yml. Antes CI migraba con el Node del runner, así que
      # nunca comprobaba que la imagen publicada supiera migrar por su cuenta.
      - name: Migrar usando la propia imagen
        run: |
          docker run --rm --network host \
            -e DATABASE_URL="$DATABASE_URL" \
            novatareas:ci node scripts/migrate-postgres.mjs

      - name: Comprobar que la imagen arranca y responde
        run: |
          docker run -d --name novatareas-ci \
            --network host \
            -e DATABASE_URL="$DATABASE_URL" \
            -e SECRET_KEY="$SECRET_KEY" \
            -e CRON_SECRET="$CRON_SECRET" \
            -e TELEGRAM_WEBHOOK_SECRET="$TELEGRAM_WEBHOOK_SECRET" \
            -e TOKEN_ENCRYPTION_KEY="$TOKEN_ENCRYPTION_KEY" \
            novatareas:ci
          for intento in $(seq 1 20); do
            if curl -fsS http://127.0.0.1:4321/api/v1/health/ready; then
              echo "La imagen responde correctamente."
              exit 0
            fi
            sleep 2
          done
          echo "La imagen no respondió a tiempo."
          docker logs novatareas-ci
          exit 1

      # Va ANTES de publicar: una imagen vulnerable falla aquí y nunca llega al
      # registro. `ignore-unfixed` evita bloquear por CVEs de Debian sin parche
      # disponible, que detendrían el trabajo sin ofrecer ninguna acción.
      - name: Analizar vulnerabilidades de la imagen
        uses: aquasecurity/trivy-action@v0.36.0
        with:
          image-ref: novatareas:ci
          severity: HIGH,CRITICAL
          ignore-unfixed: true
          exit-code: '1'
          format: table

      - name: Calcular las etiquetas
        if: github.ref == 'refs/heads/main'
        id: etiquetas
        run: |
          SHA_CORTO=$(git rev-parse --short=7 HEAD)
          VERSION=$(awk '/^release:/{f=1} f && /^  version:/{gsub(/["[:space:]]/,"",$2); print $2; exit}' release-manifest.yml)
          if [ -z "$VERSION" ]; then
            echo "No se pudo leer release.version de release-manifest.yml"
            exit 1
          fi
          echo "sha_corto=$SHA_CORTO" >> "$GITHUB_OUTPUT"
          echo "version=$VERSION" >> "$GITHUB_OUTPUT"
          echo "Etiquetas: sha-$SHA_CORTO, $VERSION, latest"

      - name: Entrar en GHCR
        if: github.ref == 'refs/heads/main'
        run: echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin

      - name: Publicar la imagen
        if: github.ref == 'refs/heads/main'
        run: |
          SHA_CORTO=${{ steps.etiquetas.outputs.sha_corto }}
          VERSION=${{ steps.etiquetas.outputs.version }}
          for etiqueta in "sha-$SHA_CORTO" "$VERSION" latest; do
            docker tag novatareas:ci "$IMAGEN:$etiqueta"
            docker push "$IMAGEN:$etiqueta"
          done
```
